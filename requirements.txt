# pandas 3.x note
#
# pip resolves pandas to 3.x here, not 2.x. pandas 3.0 made copy-on-write the
# default and changed the default string dtype. Nothing in Phase 1 touches
# that, but from Phase 2 onward, tutorial or Stack Overflow code that relies on
# chained assignment mutating a DataFrame in place will silently no-op instead
# of working. If a data transformation behaves oddly, check this first. The
# escape hatch is pinning pandas>=2.2,<3.
